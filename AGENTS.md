# AGENTS.md

## Project shape
- RFGuess is a Python 3.11 desktop app, not an installed package. The real entrypoint is `main.py`, which launches the PyQt UI and wires `ui/slots.py`.
- For user-facing workflow changes, start from `ui/slots.py`. It is the main controller between the generated UI and the training / generation logic.
- Core training and database orchestration live under `Scripts/`, especially `Scripts/main_General_PII_Mode.py` and `Scripts/databaseInit.py`.
- Runtime algorithm and DB configuration live in `Parser/Config.py`.

## Setup and run
- Preferred setup is `uv`, not editable/package install:
  - `uv sync`
  - `uv run python main.py`
- Pip fallback is supported:
  - `pip install -r requirements.txt`
  - `python main.py`
- The repo pins Python to `>=3.11,<3.12` and `.python-version` is `3.11`.

## Database and environment
- Local MySQL is expected for normal training flows. Start it with `docker-compose up -d`.
- Default DB URL is `mysql://root:root@127.0.0.1:3307/rfguess`.
- The runtime DB override is `RFGUESS_DATABASE_URL` in `Parser/Config.py`. Prefer that env var over hardcoding connection changes.
- `docker-compose.yml` mounts `user.sql` into `/docker-entrypoint-initdb.d/user.sql`, so the local container initializes schema/data on first startup.

## Tests and verification
- The test suite uses `unittest` discovery/module invocation, not repo-level pytest config.
- Verified focused command:
  - `uv run python -m unittest Tests.test_config_runtime -q`
- Broad suite command used in repo planning docs:
  - `uv run python -m unittest discover -q`
- Many heavier tests are opt-in:
  - `RFGUESS_RUN_DB_TESTS=1` enables database integration tests.
  - `RFGUESS_RUN_EXTERNAL_TESTS=1` enables external/artifact-heavy tests.
- When changing DB logic, config, parsers, generators, or classifier loading, check whether the relevant tests are gated before assuming coverage is missing.

## File-specific gotchas
- `ui/mainWindow.py` is generated by `pyuic5`; manual edits will be overwritten. Put behavior in `ui/slots.py` or regenerate the UI file deliberately.
- `Parser/Config.py` still exposes mutable module-level `DatabaseUrl`; some tests verify both the env-based getter and runtime setter behavior, so preserve both unless intentionally refactoring callers.
- Built artifacts and generated outputs such as `*.clf`, `dist/`, `build/`, and `_*.txt` / `_*.md` are ignored by git. Do not rely on them as tracked inputs.

## Dependency workflow quirks
- `pyproject.toml` is the source of truth for dependencies, but `.pre-commit-config.yaml` still runs Poetry hooks (`poetry-check`, `poetry-lock`, `poetry-export`, `poetry-install`). If you change dependencies, expect lock/export churn around `poetry.lock` and `requirements.txt`.
- `requirements.txt` is hash-pinned and should not be hand-edited casually.

## macOS note
- If `mysqlclient` fails to build, follow the README workaround with Homebrew `mysql-client` + `pkg-config` and set `PKG_CONFIG_PATH` before retrying `uv run python main.py`.
